# 2.4G 接收器：Mac 勿扰键（F6）对接说明

键盘在 Mac 布局下按 F6，USB 和蓝牙模式直接发送 Generic Desktop `0x9B`（System Do Not Disturb），Mac 收到后切换勿扰模式，无需任何系统设置。

2.4G 模式下，Mac 只和接收器通信，所以需要接收器把键盘发来的"系统键包"转成同样的 `0x9B` 报告。键盘这一侧已经实现，本文说明接收器需要做的修改。

## 1. 键盘发出的 RF 数据包

格式与多媒体键包相同，长度 `iRF_K_LENGTH_OTHER`（3 字节），加密包类型为 `PACKET_TYPE_FOR_OTHERS`。

| 字节 | 值 | 说明 |
|---|---|---|
| 0 | `0x80` | `iRF_K_TYPE_KB` |
| 1 | `0x40` | `iRF_K_OTHER_SYS`（系统键包） |
| 2 | 位图 | 见下表 |

第 2 字节的位图沿用 `key_code_define.h` 里原有的系统键按位定义，勿扰用新增的第 3 位：

| 位 | 宏 | 含义 | 对应的 Generic Desktop 用法 |
|---|---|---|---|
| bit0 | `iSYS_POWER` | 电源（原有定义，键盘目前不发） | `0x81` |
| bit1 | `iSYS_SLEEP` | 睡眠（原有定义，键盘目前不发） | `0x82` |
| bit2 | `iSYS_WAKEUP` | 唤醒（原有定义，键盘目前不发） | `0x83` |
| **bit3** | **`iSYS_DO_NOT_DISTURB`** | **勿扰（新增）** | **`0x9B`** |
| bit4~7 | — | 保留，发 0 | — |

发送时机：
- **按下 F6**：发位图 `0x08`；**松开**：发位图 `0x00`。每次状态变化连发 8 包。
- **按住不放**：每约 64 个发送周期补发 2 包（保活），内容与当前状态相同。

接收器应按"状态"处理：只在位图变化时向电脑发送报告，重复包忽略。

## 2. 接收器需要修改的地方

### 2.1 USB 报告描述符新增 System Control 集合

建议使用和键盘 USB / 蓝牙相同的格式（与 QMK `host_system_send()` 一致，已在 macOS 上验证可切换勿扰）。`<ID>` 换成接收器里未被占用的报告 ID：

```
05 01        Usage Page (Generic Desktop)
09 80        Usage (System Control)
A1 01        Collection (Application)
85 <ID>        Report ID (<ID>)
19 01          Usage Minimum (0x01)
29 B7          Usage Maximum (0xB7)
15 01          Logical Minimum (1)
26 B7 00       Logical Maximum (0xB7)
95 01          Report Count (1)
75 10          Report Size (16)
81 00          Input (Data, Array, Absolute)
C0           End Collection
```

报告内容为 3 字节：`[<ID>, 用法低字节, 用法高字节]`。

### 2.2 收到系统键包时发送报告

| 收到的位图 | 发给电脑的报告 |
|---|---|
| bit3 = 1 | `[<ID>, 0x9B, 0x00]`（勿扰按下） |
| bit3 = 0 | `[<ID>, 0x00, 0x00]`（释放） |

如需同时支持 bit0~bit2，按 `0x81`/`0x82`/`0x83` 映射。数组格式同一时刻只能报一个用法，多个位同时为 1 时按优先级取一个即可。

## 3. 兼容性

- **旧接收器**：如果它只解析第 2 字节的 bit0~bit2，bit3 会被忽略，不会误触发电源或睡眠。按 F6 没有反应，但不会出问题。
- **如果接收器方案是把第 2 字节直接当 Generic Desktop 用法值转发**（而不是按位），把键盘 `key_code_define.h` 里的 `iSYS_DO_NOT_DISTURB` 改成 `0x9B` 即可，接收器不需要再做映射。
