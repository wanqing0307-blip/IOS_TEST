# 2.4G 接收器：Mac 勿扰键（F6）修改方案

键盘在 Mac 布局下按 F6，USB 和蓝牙模式直接发送 Generic Desktop `0x9B`（System Do Not Disturb），Mac 收到后切换勿扰（专注）模式，不需要任何系统设置。

2.4G 模式下 Mac 只和接收器通信。勿扰在 macOS 上**只能**用 Generic Desktop 页的 `0x9B` 发送，Consumer（多媒体）页没有对应的用法（苹果《Accessory Design Guidelines》第 14.1 节表 14-3、表 14-4），所以不能借用接收器现有的多媒体报告，需要接收器新增一个系统控制报告，把键盘发来的值转发给 Mac。

**键盘这一侧已经实现，不用再改。** 下面是接收器要做的修改，一共 4 处，约 40 行代码。

## 1. 键盘发出的数据

格式和多媒体键包相同，长度 `iRF_K_LENGTH_OTHER`（3 字节），加密包类型 `PACKET_TYPE_FOR_OTHERS`。

| 字节 | 值 | 说明 |
|---|---|---|
| 0 | `0x80` | `iRF_K_TYPE_KB` |
| 1 | `0x40` | `iRF_K_OTHER_SYS`（系统键包） |
| 2 | 用法值 | Generic Desktop 用法 ID 的低字节：按下勿扰为 `0x9B`，松开为 `0x00` |

发送时机（2.4G 每 4 ms 一个发送时隙）：

- 按下、松开时，各连发 8 包（约 32 ms）。
- 按住不放时，约每 256 ms 补发 2 包，内容和当前状态相同。
- 键盘只会发 `0x9B` 和 `0x00` 两个值。

## 2. 修改方案

以下代码按键盘工程 USB 模式里已经实测可用的写法给出（同一套 OnMicro SDK，接收器工程里通常有同名的文件、宏和变量）；名字不同的地方，找到对应位置照着改即可。

### 2.1 报告 ID（`usb_cfg_info.h`）

新增一个接收器里**没有用过**的报告 ID。键盘工程里多媒体是 `0x01`、鼠标 `0x02`、扩展键盘 `0x05`、自定义 `0x0E`，`0x03` 空着：

```c
#define iREPORT_ID_SYS_KEY      0x03            // 系统控制报告（Mac 勿扰）
```

### 2.2 报告描述符（`usb_descriptor.h`）

在**多媒体报告所在接口**的报告描述符里（键盘工程是 `HID_ReportDescriptor_Define[]`），紧接着多媒体（Consumer）集合后面加：

```c
//SYSTEM CONTROL REPORT（系统控制报告）
    HID_UsagePage(HID_USAGE_PAGE_GENERIC),
    HID_Usage(HID_USAGE_GENERIC_SYSTEM_CTL),
    HID_Collection(HID_Application),
      HID_ReportID(iREPORT_ID_SYS_KEY),
      HID_UsageMin(0x01),
      HID_UsageMax(0xB7),
      HID_LogicalMin(1),
      HID_LogicalMaxS(0x00B7),
      HID_ReportCount(1),
      HID_ReportSize(16),
      HID_Input(HID_Data | HID_Array | HID_Absolute),
    HID_EndCollection,
```

对应的原始字节（共 24 字节，`xx` 为报告 ID）：

```
05 01 09 80 A1 01 85 xx 19 01 29 B7 15 01 26 B7 00 95 01 75 10 81 00 C0
```

注意：

- 配置描述符里该接口 HID 描述符的报告描述符长度（`wDescriptorLength`）：键盘工程用 `sizeof(HID_ReportDescriptor_Define)` 计算，会自动变；如果接收器里是写死的数字，要加 24。
- 描述符加在哪个接口，报告就要从那个接口的中断端点发（见 2.4）。

### 2.3 收到系统键包（接收器处理键盘数据包的地方）

先定义发送标志和变量（`bsys_data_send` 选 `m_data_flag` 里没用过的一位，键盘工程用的是第 5 位）：

```c
#define bsys_data_send      (1<<5)              // 系统控制报告待发

uint8_t                     sys_data;           // 当前系统控制用法值（0 = 松开）
uint32_t                    sys_rx_rtc;         // 最近一次收到系统键包的时间
```

在接收器解密后处理键盘数据包（`iRF_K_TYPE_KB`）的地方，多媒体键包（`iRF_K_OTHER_MMK`）的处理旁边加：

```c
if(iRF_K_OTHER_SYS == buf[1])                   // 系统键包 [0x80, 0x40, 用法值]
{
    sys_rx_rtc = drv_rtc_read(OM_RTC);          // 超时释放用
    // 只在值变化时上报，重复包忽略；上一个报告还没发出时先不更新，
    // 键盘同一状态会连发 8 包，下一包再更新，保证按下、松开都能上报
    if((buf[2] != sys_data) && (0 == (m_data_flag & bsys_data_send)))
    {
        sys_data = buf[2];
        m_data_flag |= bsys_data_send;
    }
}
```

注意：

- **`buf[1]`（字节 1）要整字节等于 `0x40`**，不能只比较高 3 位（`iRF_K_OTHER_MASK`）：协议里 `0x41` 是 FN 包（`iRF_K_OTHER_FN`），高 3 位和 `0x40` 相同。
- 如果接收器里已经有处理 `iRF_K_OTHER_SYS` 的代码（比如按位当作电源、睡眠键），换成上面的写法。
- `buf[2]`（字节 2）原样作为 16 位用法值的低字节，高字节固定 0，不需要转换。

### 2.4 USB 发送（`usb_user_process.c` 的 `usb_data_process()`）

1）开头判断有没有数据要发时，要把新标志算进去。键盘工程原来写死成 `0x1F`，漏掉第 5 位，单独按 F6 时报告一直发不出去：

```c
    if(0==(m_data_flag&(bmouse_data_send|bstd_kb_data_send|bmmk_data_send
                       |bstd_ex_data_send|bhid_data_send|bsys_data_send)))
        return;
```

2）在多媒体报告所在端点（键盘工程是 EP3）的发送分支里，紧跟多媒体报告的分支后面加：

```c
        else if(m_data_flag & bsys_data_send)
        {                                       // 系统控制报告
            m_data_flag &= ~bsys_data_send;

            fifo_epn = (volatile uint8_t *)&OM_USB->EPnFIFO[3];
            *fifo_epn = iREPORT_ID_SYS_KEY;
            *fifo_epn = sys_data;               // 16 位用法值，低字节
            *fifo_epn = 0;                      // 高字节

            OM_USB->TXCSR1 |= USB_TXCSR_P_TXPKTRDY;
            g_USB_Ep_Status[3] = EP_TX;
        }
```

发出去的报告：按下 `[03, 9B, 00]`，松开 `[03, 00, 00]`。

### 2.5 超时释放（接收器主循环）

按住 F6 时键盘断电或离开范围，接收器收不到松开包，Mac 会一直认为 F6 按着。按住期间键盘约每 256 ms 补发一次，超过 1 秒没收到就自动释放：

```c
if((0 != sys_data) && (0 == (m_data_flag & bsys_data_send))
   && (mMS_TO_TICK(1000) < (drv_rtc_read(OM_RTC) - sys_rx_rtc)))
{
    sys_data = 0;
    m_data_flag |= bsys_data_send;              // 发送 [03, 00, 00]
}
```

（`mMS_TO_TICK(ms)` 和键盘工程相同：`((ms)<<5)`，RTC 为 32 kHz。）

## 3. 自测清单

接收器烧录后**拔插一次**，让电脑重新读取描述符。键盘用 Mac 布局、2.4G 模式：

| 测试 | 期望结果 |
|---|---|
| Mac 上按一下 F6 | 勿扰（专注）模式打开；再按一下关闭 |
| 按住 F6 5 秒再松开 | 只切换一次 |
| 按住 F6 时关掉键盘电源 | 1 秒内释放，之后按其他键正常 |
| F5 | 听写（走原多媒体通道，`[80 20 CF]`；接收器多媒体报告的逻辑最大值要不小于 `0xCF`） |
| 音量、播放、亮度等多媒体键 | 和修改前一样 |
| Windows 上按 F6 | 没有反应，也不会关机、睡眠（Windows 不处理 `0x9B`） |
| 旧固件的键盘配新接收器 | 和修改前一样（旧键盘不发系统键包） |

用 USB 抓包或 HID 查看工具可以直接看到报告：按下 `03 9B 00`，松开 `03 00 00`。

## 4. 现有接收器的实测结果

用现有接收器测试时，键盘已经按第 1 节发送 `[0x80, 0x40, 0x9B]`：按 F6 **没有任何反应**，也没有误触发电源或睡眠。所以：

- 现有接收器不转发系统键包，需要按第 2 节升级接收器固件；
- 升级之前，2.4G 下按 F6 没有作用，但不会造成任何副作用。USB、蓝牙下不受影响。
